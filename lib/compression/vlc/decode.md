# Декодирование 

### Процесс декодирование:

#### ~~1. Преобразование шестнадцатеричных чанков в двоичные:~~ (не актуален)
> Изначально сжатый файл представляет собой набор шестнадцатеричных чанков. 
Каждый такой чанк, по сути, является числом, записанным в шестнадцатеричном виде. 
Первым шагом является приведение каждого из них к двоичному виду. 
Для этого создается функция, которая из полученной строки будет доставать шестнадцатеричные чанки, а затем преобразовывать их в двоичные.
#### 2. Объединение двоичных чанков: 
> Все полученные двоичные чанки объединяются в одну большую двоичную строку
#### 3. Декодирование двоичной строки в исходный текст: 
> Эта строка является последовательностью двоичных кодов из таблицы кодирования. 
> Необходимо поочередно находить эти коды в таблице и сопоставлять их символам.
#### 4. Восстановление исходного текста
> На выходе получается исходный текст

### Методы поиска и их оптимизация:
#### * Перебор
> Самый простой способ — это искать перебором по таблице кодирования. 
> Берется часть двоичной строки, проверяется ее наличие в таблице, если нет — берется больше символов и так далее.
> 
> Сложность алгоритма составляет `O(n * m)`
> n - количество символов
> m - размер таблицы

#### * Хеш-таблицы
> Использование хеш-таблиц может ускорить поиск по таблице кодирования, так как поиск происходит за "константное время" (в среднем). 
> 
> Сложность алгоритма составляет ~`O(n)` 
> 
> Недостатки:
> * константное время поиска гарантируется лишь в среднем.
> * необходимость учитывать коллизии.
> * вычислять хеш для каждого значения.
> 
> Поэтому хеш-таблицы не всегда являются оптимальным решением.

#### * Бинарное дерево (предпочтительный подход): 
> Это простой и быстрый способ поиска. Так как двоичная строка состоит из нулей и единиц, это наводит на мысль об использовании бинарного дерев
